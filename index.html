About TodaTrack

TodaTrack is a real-time digital monitoring system designed specifically for the TSU-SI TODA (Tricycle Operators and Drivers Association) to bridge the communication gap between students and tricycle drivers. The system addresses the persistent problem of student uncertainty regarding ride availability, especially during peak hours (6:00 PM – 9:00 PM) or inclement weather.

Built with Object-Oriented Programming principles, TodaTrack provides a comprehensive solution for tracking tricycles, monitoring drivers, and managing trips efficiently. The system ensures real-time synchronization of data and implements robust security measures through encapsulation and Row-Level Security (RLS).

Main Features

🚖 Tricycle Registration

Easy registration system for tricycles and drivers. Each tricycle is registered with a unique plate number, driver information, and passenger capacity. The system maintains a complete database of all registered vehicles and their current status.

🚀 Trip Startups

Seamless trip creation and assignment system. Students can request trips by specifying their destination, passenger count, and preferred route. The system automatically assigns available tricycles or queues the request for the next available driver.

📊 Trip Archiving

Complete trip history and analytics. All completed trips are archived with detailed information including route, fare, passenger count, timestamps, and assigned driver. This data provides valuable insights for operations management.

⚡ Real-Time Tracking

Live status updates for all tricycles and trips. Students can see waiting trips in real-time, while drivers receive instant notifications about new trip requests. The system ensures everyone stays informed about current operations.

📱 User-Friendly Interface

Intuitive design for both students and drivers. The student side displays waiting trips with clear information, while the driver dashboard provides easy access to all necessary functions for managing their service.

🔒 Secure Operations

Built-in security measures including data encapsulation and Row-Level Security (RLS). The system ensures that sensitive information is protected and users can only access data relevant to their role.

Real-Time Sync Functionality

TodaTrack implements a real-time synchronization system that keeps all users updated with the latest information about tricycles and trips. This ensures that students see current trip availability and drivers receive immediate notifications about new requests.

How Real-Time Sync Works

The system uses a polling mechanism that updates the display every 3 seconds. In a production environment, this would be replaced with WebSockets or Server-Sent Events for more efficient real-time communication. 

// Real-time update implementation
function simulateRealTimeUpdates() {
    // Update waiting trips display
    if (typeof updateWaitingTripsDisplay === 'function') {
        updateWaitingTripsDisplay();
    }
    
    // Update driver dashboard
    if (typeof updateDriverDashboard === 'function') {
        updateDriverDashboard();
    }
}

// Start real-time updates (every 3 seconds)
setInterval(simulateRealTimeUpdates, 3000);

Benefits of Real-Time Sync

  • Immediate Updates - Students see new trips as soon as they're created
  • Reduced Wait Times - Drivers are notified instantly about new requests
  • Better User Experience - No need to manually refresh the page
  • Accurate Status - Always shows the current state of all trips and tricycles

Encapsulation and RLS Security

Security is a fundamental aspect of TodaTrack. The system implements multiple layers of security to protect user data and ensure proper access control.

Object-Oriented Encapsulation

The system uses OOP principles to encapsulate data and behavior. Each class (Tricycle, Trip) has private data that can only be accessed through defined methods, preventing unauthorized modifications. 

class Tricycle {
    constructor(plateNumber, driverName, capacity) {
        this.plateNumber = plateNumber;
        this.driverName = driverName;
        this.capacity = capacity;
        this.status = 'available';
        this.currentTrip = null;
    }

    // Getter methods provide controlled access
    getStatus() {
        return this.status;
    }

    // Methods validate state before making changes
    startTrip(trip) {
        if (this.status === 'available') {
            this.status = 'on-trip';
            this.currentTrip = trip;
            return true;
        }
        return false; // Prevents invalid state changes
    }
}

Row-Level Security (RLS)

In a production environment with a database backend (such as Supabase or PostgreSQL), TodaTrack would implement Row-Level Security policies to ensure:

  • Drivers can only view and modify their own tricycle information
  • Students can view all waiting trips but cannot modify trip data
  • Trip assignments are validated at the database level
  • Historical trip data is protected from unauthorized access
Production Note: When deploying with a real database, ensure RLS policies are configured to match user roles and permissions. Never expose database credentials in client-side code.

Example Code Implementations

Registering a Driver

The driver registration function demonstrates input validation, duplicate checking, and proper object instantiation: 

function registerDriver(plateNumber, driverName, capacity) {
    // Validation
    if (!plateNumber || !driverName || !capacity) {
        return {
            success: false,
            message: 'All fields are required'
        };
    }

    // Check for duplicates
    const exists = tricycles.find(t => t.plateNumber === plateNumber);
    if (exists) {
        return {
            success: false,
            message: 'Tricycle with this plate number already exists'
        };
    }

    // Create and store new tricycle
    const newTricycle = new Tricycle(plateNumber, driverName, capacity);
    tricycles.push(newTricycle);

    return {
        success: true,
        message: 'Driver registered successfully',
        tricycle: newTricycle
    };
}

Creating a Trip

The trip creation function handles validation, auto-assignment, and maintains trip records: 

function createTrip(destination, passengerCount, fare, route) {
    // Validation
    if (!destination || !passengerCount || !fare || !route) {
        return {
            success: false,
            message: 'All fields are required'
        };
    }

    if (passengerCount < 1) {
        return {
            success: false,
            message: 'Passenger count must be at least 1'
        };
    }

    // Create trip object
    const newTrip = new Trip(tripIdCounter++, destination, 
                           passengerCount, fare, route);
    trips.push(newTrip);

    // Try auto-assignment
    const availableTricycle = findAvailableTricycle(passengerCount);
    if (availableTricycle) {
        assignTripToTricycle(newTrip.id, availableTricycle.plateNumber);
    }

    return {
        success: true,
        message: 'Trip created successfully',
        trip: newTrip
    };
}
